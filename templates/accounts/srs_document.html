Introduction

1.1 Purpose

This Software Requirements Specification (SRS) defines the complete functional and non-functional requirements for CourseCart — an online vocational skills training platform designed to provide affordable, accessible, and certified vocational education to Tanzanian youth. The platform addresses the critical gap between unemployed youth seeking marketable skills and the high cost and geographic inaccessibility of traditional vocational training centers.

1.2 Scope

CourseCart is a Django-based web application that connects students with vocational instructors. The system facilitates user registration with role-based access (Student/Instructor), course creation and management, course browsing with search/filter, enrollment with simulated payment processing, lesson delivery through multiple formats (YouTube, PDF, video, text), progress tracking with completion certificates, and a comprehensive notification system.

Overall Description

2.1 Product Perspective

CourseCart is a standalone web application serving as an alternative to physical vocational training centers. It operates on the Django MTV architecture with SQLite for development and PostgreSQL for production. The system simulates payment gateways in its initial release with planned integration of real Tanzanian payment systems (M-Pesa, Tigo Pesa, NMB, CRDB).

  • Django MTV architecture — no REST framework in initial release
  • Vanilla CSS/JS — no external frontend frameworks

Non-Functional Requirements

4.1 Performance

NFR-P01Page load time< 3 seconds on 3G

4.2 Security

  • Password hashing via Django PBKDF2 algorithm
  • CSRF protection on all POST requests
  • XSS protection via Django template auto-escaping
  • SQL injection prevention via Django ORM parameterized queries
  • Role-based access control (Student/Instructor/Admin)
  • Secure file upload validation (extension + MIME type checking)
  • Production: HTTPS enforcement, secure cookies, HSTS headers

4.3 Usability

  • Fully responsive design (mobile, tablet, desktop)
  • Consistent Teal + Amber + White color scheme
  • Intuitive navigation with clear call-to-action buttons
  • Form validation with descriptive error messages
  • Accessible — WCAG 2.1 AA compliant

4.4 Reliability & Scalability

  • System uptime: 99.5% (excluding planned maintenance)
  • Modular app structure for easy feature addition
  • Database migration path: SQLite → PostgreSQL
  • Payment service designed for real gateway integration

Use Case Descriptions

UC-01: Student Enrollment & Payment

ActorStudent
PreconditionStudent authenticated; course published and not previously enrolled
Main Flow1. Student browses courses → 2. Clicks course detail → 3. Clicks "Enroll Now" → 4. System checks duplicate → 5. Enrollment created → 6. Free course: instant access / Paid: redirect to checkout → 7. Student selects payment method → 8. System simulates processing → 9. On success: enrollment activated, lessons accessible → 10. Notifications sent to student and instructor
PostconditionEnrollment payment_status='completed'; student can access all lessons

UC-02: Instructor Publishes Course with Lessons

ActorInstructor
PreconditionInstructor authenticated
Main Flow1. Instructor navigates to "Create Course" → 2. Fills multi-step form (title, category, price, description, thumbnail) → 3. Course auto-published → 4. Adds lessons (YouTube/PDF/Video/Text) → 5. Lessons auto-ordered → 6. Course visible to students
PostconditionCourse status='published'; lessons available for enrolled students

UC-03: Student Completes Course & Receives Certificate

ActorStudent
PreconditionEnrollment active; payment completed
Main Flow1. Student accesses lesson → 2. Views content (video/PDF/text) → 3. Clicks "Mark Complete" → 4. Progress recalculated → 5. Repeat for all lessons → 6. On 100% completion: enrollment marked complete → 7. Certificate issued if course setting enabled → 8. Notification sent
PostconditionEnrollment is_completed=True; certificate issued if applicable
